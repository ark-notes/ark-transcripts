# 深挖方法（用户确认 · 2026-10-01）

## 核心原则：**去重不丢信息**

> 用户原话：「重复的肯定是没有价值的，只需要找出重复里的不同之处就行。」

## 方法：主题归并 + 增量提取

### ❌ 错误做法
逐支产出 30 份文件 → 70% 内容重复 → 不是"精华"，是"重复笔记"

### ✅ 正确做法
```
1. 完整读每支（100%，分段）
2. 识别「主题」（如：治理提案 / 成交话术 / 收益计算）
3. 归并到对应主题文件
4. 重复内容：只记录「不同之处」（新角度、新数据、新案例）
5. 新内容：完整写入
```

## 审查层（2026-10-01 新增 · 用户要求）

> 用户原话：「严谨并且有专业的审查能力，可以审查出其中的错误、矛盾点等等，归属于错误、不确定方向的，都需要去审查，并通过大数据对比进行优化。」

**每份成果必须过「五类审查」（详见 `审查清单.md`）：**
1. 事实错误（数据/时间线/术语）
2. 内部矛盾（同素材或跨素材冲突）
3. 不可验证（绝对化/效果对比/无出处数字）
4. 逻辑问题（因果倒置/以偏概全）
5. 风险表述（承诺收益/保证安全）

**输出**：每份成果末尾必须有「⚠️ 审查发现」章节。

# 归并标准 v2（用户确认 · 2026-10-01）

> 用户确认：「去重信息，但保留不同说法」

## 四条处理规则

| 类型 | 判断 | 处理 |
|---|---|---|
| **① 完全重复**（逐字一样） | 信息已存在 | ✅ **跳过** |
| **② 意思相近但说法不同** | 信息重复，**表达不同** | ⚠️ **保留说法**，标注「同 X 号成果」 |
| **③ 新角度 / 新数据 / 新案例** | 信息新增 | ✅ **完整保留** |
| **④ 更好的表达** | 说法更优 | ✅ **替换或并列** |

## 核心原则

> **去重的是「重复的信息」，不是「重复的说法」。**
> **因为用户学的是「怎么讲」—— 多一种讲法 = 多一件武器。**

## 示例

**「20 号提案」的多种说法（都保留）：**

| 说法 | 来源 | 保留理由 |
|---|---|---|
| 「用机制代替人性，把 (3,3) 做成机制」 | 大香蕉 | 理论高度 |
| 「涡轮前面设关卡，0.5 折」 | 文雄 | **最通俗** |
| 「像水库大坝的阀门」 | 尼克 | **最好懂** |
| 「让价格稳定，不让同时抛压」 | 其他 | 最直白 |

**→ 四种说法并存，用户按对象选。**

## 标注方式

```
## 20 号提案（多种说法）
- 【理论版】…
- 【通俗版】…（同 07 号成果）
- 【比喻版】…（同 07 号成果）
```
