# 内容审查清单（每份成果必过）

> 用户要求：「严谨并且有专业的审查能力，可以审查出其中的错误、矛盾点等等，归属于错误、不确定方向的，都需要去审查，并通过大数据对比进行优化。」

## 审查五类问题

### ① 事实错误（有硬证据可反驳）
| 特征 | 处理 |
|---|---|
| 数据与官方/链上不符 | **标注 + 纠正** |
| 时间线矛盾（同一事件不同日期） | **交叉验证，取多数/官方** |
| 术语用错（如把 RBS 说成 RWA） | **纠正** |
| 讲师口误 | **标注原话 + 更正** |

### ② 内部矛盾（同一素材/不同素材冲突）
| 特征 | 处理 |
|---|---|
| 同一讲师的数字前后不一 | **标注两处，指出矛盾** |
| 不同讲师说法冲突 | **列出双方 + 判断哪个更可信** |
| 与官方文档冲突 | **以官方为准，标注讲师差异** |

### ③ 不可验证（无法证实/证伪）
| 特征 | 处理 |
|---|---|
| 「唯一」「通通」「碾压」 | **改严谨表述** |
| 「效果更好」类对比 | **删除或改"差异"** |
| 无出处的数字 | **标注"讲师口述，待核"** |
| 未来预测 | **标注"预测，非承诺"** |

### ④ 逻辑问题
| 特征 | 处理 |
|---|---|
| 因果倒置 | **指出** |
| 以偏概全 | **指出** |
| 循环论证 | **指出** |

### ⑤ 风险表述（法律/合规）
| 特征 | 处理 |
|---|---|
| 承诺收益 | **删除** |
| 保证安全 | **改"设计目标"** |
| 与监管政策冲突的表述 | **标注风险** |

## 大数据对比方法

1. **多素材交叉**：同一主题 >3 位讲师讲 → 取共识部分
2. **官方校验**：知识库 > 链上数据 > 讲师口述
3. **时间排序**：后讲的可能修正先讲的
4. **数字验证**：能算的自己算一遍（如系数 0.5/0.6/0.7 那组）

## 输出格式

审查发现 → 写进成果文件的「⚠️ 审查发现」章节：

```
### ⚠️ 审查发现
| # | 问题 | 原文 | 问题类型 | 建议 |
|---|---|---|---|---|
| 1 | ... | ... | 事实错误 | ... |
```
